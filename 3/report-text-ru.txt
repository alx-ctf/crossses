1. ЦЕЛЬ РАБОТЫ
================================================================================
Разработать веб-приложение на ASP.NET Core (Minimal API), которое при обращении
к HTTP-endpoint возвращает данные из базы данных в формате JSON. Приложение
должно использовать Entity Framework Core, конфигурацию через appsettings.json,
внедрение зависимостей (DI) и собственный сервис обработки данных.

Предметная область и модель данных совпадают с практической работой №2 (блог:
записи BlogPost и комментарии Comment, SQLite).

================================================================================
4. КОНФИГУРАЦИЯ (appsettings.json)
================================================================================
Секция ConnectionStrings:
  "BlogDb": "Data Source=blog_variant2.db"
  Чтение в Program.cs: builder.Configuration.GetConnectionString("BlogDb")

Секция AppSettings (пользовательские настройки, ≥1 как требует задание):
  AppName  — отображаемое имя API (в ответе /api/data и /api/config)
  Version  — версия приложения (поле appVersion в JSON)
  MaxItems — максимум записей блога, возвращаемых сервисом (Take в LINQ)

Переопределение в appsettings.Development.json:
  AppName = "Blog API (Development)", Version = "1.0-dev", MaxItems = 5

Способы доступа к настройкам в коде:
  • IConfiguration.GetConnectionString("BlogDb")
  • IConfiguration.GetSection("AppSettings")["AppName"]
  • IOptions<AppSettings> через Configure<AppSettings>() — в BlogDataService

================================================================================
5. DEPENDENCY INJECTION (РЕГИСТРАЦИЯ СЕРВИСОВ)
================================================================================
В Program.cs (WebApplicationBuilder builder):

  builder.Services.Configure<AppSettings>(
      builder.Configuration.GetSection("AppSettings"));
      — привязка секции JSON к классу AppSettings (паттерн Options).

  builder.Services.AddDbContext<BlogDbContext>(options =>
      options.UseSqlite(connectionString));
      — контекст EF Core, время жизни Scoped (по умолчанию для DbContext).

  builder.Services.AddScoped<IDataService, BlogDataService>();
      — собственный сервис: интерфейс IDataService, реализация BlogDataService,
        время жизни Scoped (один экземпляр на HTTP-запрос).

Внедрение в обработчики Minimal API:
  • MapGet("/api/data", async (IDataService dataService, CancellationToken ct) => ...)
      — IDataService передаётся параметром метода (рекомендуемый способ для Minimal API).
  • MapGet("/api/config", (IConfiguration configuration) => ...)
      — IConfiguration внедряется автоматически контейнером.

При старте приложения создаётся scope, применяются миграции и сидинг:
  using (var scope = app.Services.CreateScope()) { ... MigrateAsync(); SeedAsync(); }

================================================================================
6. ОПИСАНИЕ КЛАССОВ И МЕТОДОВ
================================================================================

--- Program.cs ---
Точка входа приложения (top-level statements).
  • WebApplication.CreateBuilder(args) — создание хоста и конфигурации.
  • Регистрация сервисов (см. раздел 5).
  • WebApplication.Build() — построение конвейера middleware.
  • Блок MigrateAsync + DbInitializer.SeedAsync — подготовка БД.
  • MapGet("/api/data", ...) — GET, возвращает Results.Ok(DataResponseDto).
  • MapGet("/api/config", ...) — GET, возвращает ConfigResponseDto из IConfiguration.
  • MapGet("/", ...) — перенаправление на /api/data.
  • app.Run() — запуск Kestrel.

--- Configuration/AppSettings.cs ---
POCO-класс для секции AppSettings.
  Свойства: AppName (string), Version (string), MaxItems (int).
  Используется с IOptions<AppSettings> в BlogDataService.

--- Models/BlogPost.cs ---
Сущность «запись блога» (таблица posts).
  Id — первичный ключ ([Key]).
  Title, Slug, Body, PublishedAt — поля с Data Annotations и [Column].
  Comments — навигационное свойство ICollection<Comment> (связь 1:N).
  Preview — вычисляемое свойство [NotMapped], не сохраняется в БД.

--- Models/Comment.cs ---
Сущность «комментарий» (таблица comments).
  Id — первичный ключ.
  AuthorName, Text, CreatedAt, PostId — столбцы БД.
  Post — навигация к BlogPost.

--- Data/BlogDbContext.cs ---
Контекст данных EF Core, наследник DbContext.
  Конструктор BlogDbContext(DbContextOptions<BlogDbContext> options) — приём опций из DI.
  Posts, Comments — свойства DbSet<T> для таблиц.
  OnModelCreating — Fluent API: уникальный индекс по Slug, связь 1:N, каскадное удаление,
    ограничения длины строк (как в практической №2).

--- Data/BlogDbContextFactory.cs ---
IDesignTimeDbContextFactory<BlogDbContext> для команды dotnet ef.
  CreateDbContext — читает appsettings.json, строит DbContextOptions с SQLite.

--- Data/DbInitializer.cs ---
Статический класс инициализации тестовых данных.
  SeedAsync(BlogDbContext db, CancellationToken) — если таблица posts пуста, добавляет
    3 записи BlogPost (требование «минимум 3 записи») с комментариями; автор «Кобец Кирилл».

--- Services/IDataService.cs ---
Интерфейс собственного сервиса (требование задания).
  GetDataAsync(CancellationToken) — Task<DataResponseDto>.

--- Services/BlogDataService.cs ---
Реализация IDataService (Scoped).
  Поля: BlogDbContext _db, AppSettings _settings.
  Конструктор: внедрение BlogDbContext и IOptions<AppSettings>.
  GetDataAsync:
    1) CountAsync — общее число постов в БД;
    2) запрос Posts с Include(Comments), AsNoTracking, OrderByDescending(PublishedAt),
       Take(MaxItems из конфигурации);
    3) проекция в PostItemDto (Id, Title, Slug, Preview, PublishedAt, CommentCount);
    4) формирование DataResponseDto с полями appName, appVersion, processedBy, items.

--- Dtos/PostItemDto.cs ---
DTO одной записи для JSON-ответа (без лишних полей сущности).

--- Dtos/DataResponseDto.cs ---
Обёртка ответа /api/data: метаданные приложения + массив items.

--- Dtos/ConfigResponseDto.cs ---
Ответ /api/config: AppName, Version, MaxItems, ConnectionStringConfigured.

--- Migrations/InitialCreate ---
Автогенерируемая миграция EF Core: создание таблиц posts и comments, индексов и FK.

7. HTTP ENDPOINTS
================================================================================

GET http://localhost:5197/api/data
  Назначение: получить данные из БД в JSON.
  Цепочка: MapGet → IDataService.GetDataAsync → BlogDbContext + BlogDataService.
  Пример полей ответа:
    appName, appVersion, totalInDatabase, returnedCount, processedBy, items[].
  Элемент items[]: id, title, slug, preview, publishedAt, commentCount.

GET http://localhost:5197/api/config
  Назначение: вывести пользовательские настройки из IConfiguration.
  Поля: appName, version, maxItems, connectionStringConfigured.

GET http://localhost:5197/
  Перенаправление 302 на /api/data.
